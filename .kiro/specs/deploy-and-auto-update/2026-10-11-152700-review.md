# Deploy-anywhere + in-app version awareness & one-click update (vf-cmdb)

The change makes the CMDB report its own baked-in version, poll the public GitHub Releases API to detect a newer tagged release, surface a non-modal "update available" pill with a one-click "Update now" button, and apply the update on the host by a pull-not-build flow (`podman auto-update` against `ghcr.io`) driven across the container/host trust boundary by a marker file + a systemd `.path` unit. It also publishes the two images via GitHub Actions, repoints the Quadlet units to `ghcr.io`, and brings the `.kiro` steering/skills/hooks and the repo memory files back in line with the live project. The whole thing holds the fixed stack: no auth, no DB credentials, generic-CRUD untouched, Podman/Quadlet-only, Alembic head unchanged at `0037`.

Watch for: nothing blocking. All five review findings are honored at code, config, and docs layers (confirmed); the preflight message for a missing `curl` is slightly misworded (NIT, confirmed); the ~1.48 MB single-chunk frontend bundle warning persists (pre-existing known issue, out of scope).

**Verdict**: APPROVED

## High-level view

The running version comes from one source — `backend/app/version.py` reads `VF_VERSION`/`VF_GIT_SHA`/`VF_BUILT_AT` from the environment baked by the Containerfiles, with `dev`/`unknown` fallbacks — and the FastAPI `version=` now reads from it instead of a `1.0.0` literal. Finding 1 is clean: the frontend's build-time version is exposed purely through a new Vite `define` key added alongside the preserved `plugins`/`server`/`test` blocks and the vitest reference header, with no tsconfig change (`vite.config.ts` is outside `tsc -b`).

GitHub detection lives in `backend/app/updates.py`: an anonymous, 10-minute-cached `latest_release_tag()` that catches every exception and returns the last-good value without advancing the cache timestamp, plus a pure strictly-newer semver compare. The `/api/v1/meta/version` endpoint never raises on an upstream failure — it returns the running version with `latest=null, updateAvailable=false`. The browser only ever calls this backend endpoint; it never touches `api.github.com` directly.

The one-click path respects the trust boundary end to end. The container only writes a marker file (`POST /admin/update`) and reads a status file (`GET /admin/update/status`); it never calls `podman`/`systemctl`. A host-side `.path` unit watches the marker and runs a oneshot `.service` that invokes the reworked update script. Finding 2 holds: the shared state dir must pre-exist and the one-time enablement is documented, and the `.service` carries no real `[Install]` section (only a comment explaining its absence). Finding 3 holds: the `.path` drops an in-flight click by design, the UI greys "Update now" while running, and there is no self-retrigger loop. Finding 4 holds: the frontend treats `requested` plus a transient `idle`/absent/unreachable window right after POST as "still starting", backed by tests on both the backend contract and the frontend component.

CI publishes `:edge`/`:sha-*` on push to `master` and `:latest`/`:vX.Y.Z` + a GitHub Release only on a `v*` tag or `workflow_dispatch`. Finding 5 is handled as the design specified — as documentation ("never move latest backward; only tag/dispatch a version >= current latest"), since the release gate is a human action, not CI logic.

### Version source and finding 1 (Vite define)

`main.py` sources `version=get_version_info().version` (the `1.0.0` literal is gone — confirmed by grep). `vite.config.ts` adds the `define` key and `import pkg from "./package.json"` while keeping the `/// <reference types="vitest" />` header, `plugins`, the `server` proxy block (`/api` + `/health` → `127.0.0.1:8000`), and the `test` block (happy-dom/globals/setupFiles/css:false) verbatim. No tsconfig was touched. `npm run build` (`tsc -b && vite build`) passes, confirming the JSON default import compiles under the type pass and the preserved blocks are intact.

### Silent-on-failure GitHub detection

`latest_release_tag()` uses a 4s `httpx` timeout, catches `Exception`, and on failure returns the cached value without advancing `fetched_at`, so a transient outage never overwrites a good tag with `None` and the retry happens on the first poll after the previous success ages past the 10-minute TTL. `is_newer`/`parse_semver` are pure and strictly-newer; `"dev"` and malformed inputs yield `False`, so a dev build never nags. The endpoint test with GitHub mocked unreachable confirms `latest=null, updateAvailable=false` and no raise. The 28-test `test_version_updates.py` suite passes (success/timeout/403/404/bad-JSON paths all covered).

### Container/host trust boundary and the admin endpoints

`POST /admin/update` calls `write_marker(latest_tag)` and returns `_read_status(default_state="requested")`; `write_marker` raises `OSError` when the bind-mount is absent, which the route translates to a 503 with the "is /var/lib/vf-cmdb mounted?" detail. `to_tag` is advisory — the host script always follows `:latest` and never parses it. The routes live in `special.router`, registered before the generic `/{resource}/{item_id}` catch-all, so `/meta/*` and `/admin/*` win rather than being read as a `{resource}`. The endpoints take no body or query params, so there is no injection surface.

### Finding 3 — in-flight click dropped, button disabled, no self-retrigger

`UpdateBadge` disables "Update now" whenever `mutation.isPending || polling` and relabels it "Updating…" while `state==="running"`. Polling runs on a `setInterval` that stops on a terminal state; there is no loop that re-POSTs the marker. The `.path` unit uses `PathChanged` with no queued second activation, and the script removes the marker on completion to avoid a restart loop. The dropped-click behavior is documented in `docs/OPERATIONS.md`.

### Finding 4 — requested / transient-idle is "still starting"

The frontend tracks a `sawActive` ref: an `idle` state is only trusted once a non-idle state has been observed, so the `requested → idle(absent file) → running` window reads as still-starting, and a caught unreachable poll during the backend restart is also treated as still-running rather than failed. The backend side is pinned by tests: `POST` returns `requested`, and `GET` before any status file returns `idle`. The frontend apply-flow test exercises `requested → idle(starting) → running → succeeded` and asserts the button is disabled during `running`.

### Host update script

Registry mode is the default: preflight (`jq`/`curl`), `flock` to serialize, pre-update backup (abort if it fails, never deleted), capture current version, `podman auto-update`, deterministic daemon-reload + restart of the four units, then a 180s (60×3s) health check requiring HTTP 200 **and** a parseable `.version` from `/api/v1/meta/version` (not merely `/health`, which the old image also answers). The outcome classifier distinguishes version-advanced / digest-refreshed-same-version / already-up-to-date, all `succeeded`, with only no-healthy-200-in-budget as `failed`. `write_status` emits exactly the camelCase keys the backend `_read_status` reads, via `jq -n` write-then-`mv`. The migration-cannot-be-rolled-back caveat is stated in the top-of-script comment and in both failure messages, pointing at `vf-cmdb-restore.sh`. The legacy source mode is preserved behind `VF_UPDATE_MODE=source`. `bash -n` passes.

The one wart: the missing-`curl` branch logs "Cannot write a JSON status without jq either" — copied from the jq branch. It still exits non-zero, so behavior is correct; only the message is off (NIT).

### CI, Containerfiles, Quadlet, and finding 5

`build.yml` publishes only `:edge` and `:sha-<shortsha>` on push to `master` (no `:latest`, no Release — confirmed). `release.yml` builds both components `:latest` + `:vX.Y.Z` and cuts a Release via `action-gh-release@v2` on both `v*` tag and `workflow_dispatch`, with `make_latest: true`. Both Containerfiles declare the `VF_*` build args wired to `ENV` (frontend in the build stage so Vite bakes `__APP_VERSION__`). The backend Quadlet unit is repointed to `ghcr.io/.../vf-cmdb-backend:latest` with `AutoUpdate=registry`, the state `Volume`, and the preserved `alias=backend`; the frontend unit likewise. Finding 5 is documentation ("never move GitHub latest backward") in `docs/OPERATIONS.md`, which matches the design decision that the release gate is a human action rather than CI branching logic. Both workflow YAMLs parse.

### Hard rules

No auth is added anywhere; the trust model (single user, private LAN, anonymous public pulls) is stated in the docs. No secret is persisted — `VF_UPDATE_DIR` in `.env.example` is a path, not a credential. The feature adds no ORM writes, so the generic-CRUD audit/naming path is untouched. Podman/Quadlet remains the only production path; no Docker/compose was reintroduced. The container never calls `podman`/`systemctl`. Alembic head is unchanged at `0037_physical_asset_theme_names` and the diff adds no migration (confirmed). The migration-rollback caveat is present at all three layers: `backend/app/updates.py` comment, the update script, and the ops/deploy docs.
